Comando para mostrar a estrutura de pastas no Terminal do Mac
O comando nativo é tree — mas ele não vem instalado no macOS por padrão. Você precisa instalá-lo primeiro via Homebrew.

1. Instalar o tree (uma vez só)
Se ainda não tem o Homebrew:

bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
Depois instale o tree:

bash
brew install tree
2. Gerar a estrutura (o comando em si)
Na pasta do projeto:

bash
tree
Isso já mostra a árvore completa, mas sem os arquivos ocultos (.gitignore, .env.example etc.).

Para ficar igual ao screenshot (mostrando .gitkeep, .dockerignore, .gitignore…):
bash
tree -a
-a = all, inclui arquivos/pastas ocultos (começados com .).

Versão mais limpa, ignorando ruído:
bash
tree -a -I '.git|node_modules|.DS_Store'
-I = ignore, exclui padrões separados por |.

.git evita listar centenas de arquivos internos do Git.

.DS_Store é o lixo que o Finder cria no Mac.

node_modules só importa se você tiver JS no projeto.

Versão com tamanhos e permissões (útil para auditoria):
bash
tree -a -h -p -I '.git|.DS_Store'
-h = tamanhos legíveis (4.0K, 1.2M).

-p = permissões (-rw-r--r--).

3. Variações úteis para este projeto
Só até 2 níveis de profundidade (visão macro):
bash
tree -a -L 2 -I '.git|.DS_Store'
-L 2 = level, desce só 2 níveis (raiz + subpastas).

Só diretórios (sem arquivos):
bash
tree -d -a -I '.git|.DS_Store'
-d = directories only.

Salvar em arquivo (para colar no README):
bash
tree -a -I '.git|.DS_Store|.gitkeep' > estrutura.txt
Exatamente como no screenshot (com srv02/ expandido e o resto recolhido)
O tree não faz colapso interativo como o VS Code. Para aquele visual "com setinhas", você tem duas opções:

Opção A — só descer o nível onde quer detalhe:

bash
tree -a -L 3 -I '.git|.DS_Store'
Opção B — usar find + sed para simular indentação (mais trabalhoso, raramente vale a pena).

Para o screenshot específico (mostrando acoes/agente/srv02/reiniciar-app.sh, mas escondendo firmware/src/), o mais próximo é:

bash
tree -a -L 4 -I '.git|.DS_Store|node_modules|vendor'
e mentalmente ignorar o que não interessa.

4. Alternativas sem instalar nada
Se não quiser usar o Homebrew:

find nativo do macOS (sem cores, mais verboso):
bash
find . -not -path '*/\.git/*' -not -name '.DS_Store' | sort | sed -e 's;[^/]*/;|____;g;s;____|; |;g'
ls -R (recursivo, mas feio):
bash
ls -R
Funciona, mas mistura diretórios e arquivos sem hierarquia visual — não recomendado para README.

fd (alternativa moderna ao find, via Homebrew):
bash
brew install fd
fd --hidden --exclude .git --exclude .DS_Store
Não desenha árvore, mas lista rápido e limpo.

5. Recomendação final
Para reproduzir o screenshot fielmente (com ocultos, sem lixo de Git/Mac):

bash
tree -a -I '.git|.DS_Store|node_modules|vendor|__pycache__|*.pyc' -L 4
Isso mostra acoes/agente/srv02/reiniciar-app.sh (nível 3) e grafana/noc/acoes.js (nível 3), esconde o vendor/ da Three.js (que polui) e não desce além do necessário.

Se quiser o mesmo resultado do screenshot (com vendor/ aparecendo mas recolhido), remova vendor do -I.

2. O caminho mais curto para "ver rodando" (sem hardware)
Se você só quer ver a tela do projeto funcionando agora, siga só isso. São 5 passos.

Passo 1 — Instalar o Docker Desktop
Windows/Mac: baixe em https://www.docker.com/products/docker-desktop/

Linux: siga https://docs.docker.com/engine/install/

Depois de instalar, abra o Docker Desktop e espere ele dizer "Engine running" (ícone verde). O Docker precisa estar aberto para os comandos funcionarem — isso está no README e é a causa nº 1 de erro de iniciante.

Como saber se deu certo: abra o terminal e rode:

bash
docker --version
Deve aparecer algo como Docker version 27.x.x. Se der "command not found", o Docker não está instalado ou o terminal precisa ser reiniciado.

Passo 2 — Baixar o projeto
Se você já tem a pasta do projeto no computador, pule. Se não:

bash
git clone <URL-do-repositório>
cd monitoramento-sala-servidores
(Se não tem Git instalado, baixe o ZIP pelo GitHub: botão verde Code → Download ZIP, e descompacte.)

Passo 3 — Criar o arquivo .env
O projeto não funciona sem o .env — é lá que ficam as senhas. O repositório traz um modelo chamado .env.example. Copie:

Windows (PowerShell):

powershell
Copy-Item .env.example .env
Mac/Linux:

bash
cp .env.example .env
Depois abra o .env num editor de texto (Bloco de Notas, VS Code...) e preencha pelo menos:

text
ZABBIX_PASSWORD=zabbix           # troque por uma senha sua
GRAFANA_ADMIN_USER=admin
GRAFANA_ADMIN_PASSWORD=admin      # troque por uma senha sua
ZABBIX_HOST_IP=192.168.x.x        # o IP do SEU computador na rede
Como descobrir o IP do seu computador:

Windows: abra o Prompt e rode ipconfig. Procure "Endereço IPv4" do adaptador Wi-Fi ou Ethernet (algo como 192.168.1.42).

Mac: Preferências do Sistema → Rede → veja o IP.

Linux: hostname -I ou ip addr.

Se você não vai usar o ESP32 agora, pode deixar ESP32_IP e NOTEBOOK_VELHO_IP em branco. O resto do sistema sobe.

Passo 4 — Subir os containers
No terminal, dentro da pasta do projeto, rode:

bash
docker compose up -d
A primeira vez demora (baixa imagens do Zabbix, Grafana, PostgreSQL — alguns GB). Vai aparecer muita linha; é normal. Espere terminar.

Como saber se deu certo:

bash
docker compose ps
Deve mostrar postgres, zabbix-server, zabbix-web, grafana todos como running (ou healthy).

Passo 5 — Abrir as telas
Abra no navegador:

O quê	Endereço	Login
Zabbix	http://localhost:8080	Admin / a senha do ZABBIX_PASSWORD
Grafana	http://localhost:3000	usuário/senha do .env
Central NOC	http://localhost:3000/d/sala-do-servidor/sala-do-servidor?kiosk&viewPanel=panel-1	(já logado)
A primeira subida do Grafana pode levar 1–2 minutos até a central aparecer. Se der erro, espere e recarregue.

Se você chegou até aqui e viu a sala 3D, o mais difícil passou. 🎉
